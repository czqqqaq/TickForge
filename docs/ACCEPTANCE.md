# 本轮修复与验收记录~

本轮按 [任务清单](../TASKS.md) 实施，源码未提交、未推送、未公开发布；历史最小闭环和重连记录保留原日期与镜像身份，本记录描述本轮源码~

## 已完成的实现与自动化验证~

- SIGINT/SIGTERM 共用停止入口，取消接收后排空已确认事件，同步信号与检查点，保留失败摘要；SIGKILL 仅承诺离线校验可用前缀，不承诺强杀瞬间处理水位已保存~
- 文本行情静默期限默认 10 秒，可通过 `--idle-timeout-ms` 固定；Ping/Pong 不刷新行情期限，超时按序记录断线并重连；每个有效数据流的最大无事件区间和 READY 时长采用录制逻辑时间统计~
- 检查点每秒与结束写入，先同步信号再追加带 CRC32 的水位、摘要及信号字节数；恢复只读取有效连续前缀，同时核对信号前缀与 WAL 业务摘要；没有检查点就不宣称证明实时一致性~
- 持久化回放使用实时同一两级队列、批次同步和计算线程，单独生成 WAL，源文件保持不变；不限速与限速共用取消机制，中断保留不完整摘要~
- 同步指标只包围 `sync_data`，引擎计算指标只包围 `Engine::on_event`，另记 flush、批次等待、队列等待、信号输出、事件年龄、排空与逐秒资源~
- 类型化行情解析移除中间 JSON 树，WAL 与持久化批次复用缓冲；原始 WAL 编码和业务结果摘要不变~

冻结源码的全量检查共 31 项测试通过：13 项单元测试，18 项集成测试；fmt、Clippy `-D warnings` 与 release 构建通过，日志见 `data/fix-validation-20261030/`~

| 故障或边界 | 实验与断言 |
|---|---|
| SIGINT / SIGTERM | 实际子进程收信号，失败退出且接收/同步/处理计数一致，保留摘要~ |
| 静默连接 | 连接只有心跳时仍触发行情静默期限，记录断线后重连~ |
| 慢同步 | 同步函数受通道控制阻塞，append/flush 后、同步完成前，计算队列仍不可见整个批次~ |
| 写盘失败 | `/dev/null` 接受写入但拒绝同步，失败批次不交付计算~ |
| 第一级队列饱和 | 本地 WebSocket 触发真实入队超时，不追加虚假结束事件~ |
| 第二级队列饱和 | 已同步批次完整保留，交付超时后停止消费下一批~ |
| SIGKILL | 实际强杀后，验证最后信号可用检查点对应前缀，后续已记录事件单独计数~ |
| 截断 / 损坏 / 篡改 | WAL、检查点与信号分别验证损坏边界，不跳过坏记录继续宣称完整~ |
| 引擎边界 | 1 秒及超限 1ns、5bps 与略超、正负阈值、不同成交量窗口全量重扫对照~ |
| 持久化回放 | 不限速、2 倍速的摘要、信号和 WAL 逐字节一致；两种回放取消均保留摘要~ |

## 测量口径与边界~

所有业务结果只使用录制时间；加速回放的性能使用本次注入时间，初始化完成后才启动注入时钟~

队内等待从发送成功确认到消费开始测量，属于可观测下界；消费者早于发送完成确认的样本不填零，分别记录在 `stages.queue1_unobserved` / `queue2_unobserved`，用直方图 count 与这些计数检查覆盖率；端到端事件年龄、持久化和接收至决策仍覆盖全部处理事件~

`resources.jsonl` 每秒记录接收/同步/处理水位、每秒速率、队列水位、CPU、RSS 和物理磁盘累计读写字节，磁盘吞吐由相邻采样差分；CPU 按单核 100% 计，页缓存可能使物理读取为零，队列峰值为发送侧观察值~

`activity.seconds` 中没有出现的秒表示该秒没有处理事件；非持久化回放仅有一级输入队列，`durable=0` 明确表示没有写入新 WAL~

本机微基准见 `data/core-optimization-validation/report.json`，固定 5,640 条真实输入、每组 25 遍、9 组中位耗时：引擎下降 54.52%、WAL 读取下降 10.38%、WAL 写入下降 30.09%；写入包含创建、同步和删除，另一轮改善为 11.42%，存在磁盘扰动，这些数值不代表全链路容量~

## 可复现入口与交付状态~

```bash
cargo build --release --locked
python scripts/acceptance.py --out data/new-acceptance --seconds 900
./target/release/yino verify --input data/new-acceptance/live
./target/release/yino report --input data/new-acceptance/live
bash scripts/package.sh data/new-delivery data/new-acceptance data/fix-validation-20261030 data/core-optimization-validation
```

`acceptance.py` 拒绝覆盖目录，记录命令、进程、UTC 时间、源码与二进制 SHA、样本和回放对照；失败保留原始证据，不自动覆盖重试；每次重试使用新目录~

本轮采纳 AI 提出的停机、静默、检查点、精确计时和解析分配建议，均用实际实验约束；没有将短时微基准外推为容量，也没有把 CRC 完整前缀、空信号一致或 `complete=true` 单独当作正式验收~

Git 当前没有提交和远端，交付身份先使用源码 SHA 清单；仓库地址、提交、推送和公开发布保持待交付，不虚构 commit 或远端镜像 digest~
