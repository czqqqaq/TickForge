# 自动重连与多连接 WAL 验证记录~

本轮按 `PLAN.MD` 优先补齐自动重连与多连接回放，验证日期为 2026-10-30；周期检查点、容量测试、完整性能报告和正式 900 秒采样仍待后续实施~

## 已实现行为~

- 每轮建连最多尝试 9 次，单次超时 15 秒；断线后的首次等待为 250ms，后续失败按指数增加至最多 5 秒，每次尝试均记录连接编号、尝试次数和等待时间~
- 采样时长从首次成功订阅开始，重连不延长截止时间；首次订阅前的握手失败不创建连接控制事件，成功后仍从连接编号 1 开始~
- 断线、重新连接及结束事件与行情共用连续序号、单调时钟原点和同步落盘链路；断线后清空窗口和报价，保留成交高水位及原目标，取得新报价和 1000 笔有效新成交后才恢复决策~
- WAL 读取器校验连续连接编号和控制事件顺序，遇到跳跃、回退、跨连接行情、断开后的行情或结束后的记录即停止，不跳过异常继续回放~
- 任何订阅后的断线都保留数据缺口证据，实时和回放均生成 `complete=false` 的统计并返回非零退出码；`verify` 独立检查 WAL 中的断线事件，不能靠修改摘要的成功标记绕过~
- 采样截止、Ctrl+C 和工作线程失败可取消建连、退避和网络入队；若入队结果尚未确认，就停止追加控制事件，保留可校验前缀并判定采样失败~

## 自动化验证~

```bash
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo build --release --locked
```

测试共 9 个单元测试和 5 个进程级本地 WebSocket 集成测试，新增验证包括以下场景~

| 场景 | 验证内容 |
|---|---|
| 重连后预热 | 第一条连接产生 LONG，第二条连接的前 999 笔有效新成交保持原目标，第 1000 笔后才允许变为 SHORT~ |
| 重连去重 | 前一条连接的成交 ID 仍被拒绝，新连接较小的报价 ID 可重新初始化~ |
| 多连接回放 | 2007 条接收、同步和处理记录一致，不限速、2 倍速及 10 倍速回放的完整业务摘要与信号一致，同时保留失败状态~ |
| 初次握手失败 | 握手失败后重试，成功前不产生虚假连接，采样计时从成功订阅开始~ |
| 网络错误 | WebSocket 正常关闭与 TCP 突然断开均触发重试，新连接仍可响应 Ping/Pong~ |
| 取消与截止 | 工作线程失败取消初始握手及饱和的网络队列入队；重连握手卡住时仍按原采样截止时间结束~ |
| WAL 异常 | 拒绝非法连接顺序，多连接日志尾部截断仅恢复完整前缀，不能标记为验收成功~ |
| 验收边界 | 手动把含缺口样本的摘要改成成功，`verify` 仍拒绝该样本~ |

本轮命令输出、文件摘要与现有真实样本的回归校验记录保存在 `data/reconnect-validation-20261030/`；本轮新增故障测试使用本地可控 WebSocket，未把它作为真实网络性能或正式采样证据~
